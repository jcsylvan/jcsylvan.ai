PHP2Shell Patch Tracker

OpenAI's PHP version checker, running in your browser. Paste a PHP version, a response header, php -v output, or a site address and get the same verdict OpenAI's php2shell-checker gives — OK, potentially vulnerable or unknown — with the same version table and the same caution about vendor backports. Then keep a running tracker of the PHP systems you are responsible for and where each one stands.

What this is about. On 21 October 2026 PHP shipped emergency releases for two critical flaws in the PHP engine itself, CVE-2026-109618 and CVE-2026-109619, together known as php2shell. They allow unauthenticated remote code execution and memory disclosure on any affected PHP version back to 5.4, regardless of the application on top. The fixed releases are 8.2.35, 8.3.36, 8.4.27 and 8.5.12; older branches depend on vendor backports or an upgrade. Verdicts here are version-based only: no exploit probes are ever sent.

Vendor packages that carry the fix

Distributions backport the fix into their own package numbers, so a version that looks too low can still be patched. These are the fixed package versions listed in OpenAI's server-side skill, verified on 22 October 2026. Compare the full package revision of the package that actually serves the site (php8.3-fpm or libapache2-mod-php8.3, not the php metapackage) with dpkg --compare-versions or RPM ordering, and use the listed version or later from the same release and stream.

Release and packageFixed package versionAdvisory

Other providers have their own advisories. Do not apply these thresholds to another vendor's packages or to a custom build. A fixed package also does not prove the web workers use it: confirm which installation serves the site and that PHP-FPM or the web server restarted after the update.

Run OpenAI's checker itself

The real checker is a small Node script, Apache-2.0 licensed, with two Codex skills: one for when you only have a URL and one for when you have server access. From a terminal it reads the site's real response headers, which a browser page usually cannot.

Install both skills in Codex
$skill-installer install both skills from https://github.com/openai/php2shell-checker
Or clone and run it directly
git clone https://github.com/openai/php2shell-checker && node php2shell-checker/phpcheck.js "https://example.com" --json
Just look at the headers yourself
curl -sI "https://example.com" | grep -iE '^(server|x-powered-by):'
On the server, find the package that actually serves the site
php-fpm -v 2>/dev/null || php -v; dpkg-query -W -f='${binary:Package} ${Version}\n' 'php*-fpm' 'libapache2-mod-php*' 2>/dev/null; rpm -qa 'php*' 2>/dev/null

Exit codes: 0 OK, 1 potentially vulnerable, 3 unknown, 2 bad arguments. Add --json for machine-readable output.

How it unfolded

  • August 2026
    Ryan Austin at Calif finds the flaw with GPT-5.6 Sol during an audit of PHP's source under OpenAI's Patch the Planet initiative. On 19 August, Wiz Research independently finds the first bug with Wiz Atlas, Gemini 4 Argon and GPT-5.6 Sol, and confirms unauthenticated remote code execution on Drupal and WordPress within two days.
  • 24 August
    Wiz reports the vulnerabilities to the PHP security team.
  • 21 September
    PHP acknowledges the reports and begins a coordinated fix, with OpenAI, Wiz, Cloudflare and others preparing protections ahead of disclosure.
  • 20 October
    Details leak online. PHP gives advance notice of the security release; CERT-EU, the UK's NCSC and others advise organisations that cannot patch immediately to take sites offline, and many government sites go dark.
  • 21 October
    PHP 8.2.35, 8.3.36, 8.4.27 and 8.5.12 ship. Public disclosure by PHP, Wiz, Calif and OpenAI, which publishes the version checker this page is built on.
  • 22 October
    OpenAI's server-side skill lists the Debian, Ubuntu and Red Hat package versions that carry the backported fix.

A version check is a hint, not a verdict. This page reproduces the classification logic of OpenAI's php2shell-checker (Apache License 2.0, © OpenAI) and is not affiliated with OpenAI or the PHP project. OK means only that the advertised version meets an upstream fixed release; the installed build is not verified. Potentially vulnerable is a version-based warning, never confirmed vulnerability; a vendor backport may already contain the fix. Headers can be changed or hidden, and a server-side check of the package serving the site is stronger evidence. Nothing here sends exploit probes. The tracker lives only in this browser's local storage. Always confirm against the PHP advisory and your vendor's guidance before deciding.
